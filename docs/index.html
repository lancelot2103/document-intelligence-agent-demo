An AI agent that is not allowed to invent a number

Most document-AI demos look great and fail quietly: the model produces a confident invoice total that happens to be wrong. This is the opposite build — arithmetic by parser and subtraction, writes blocked until a human approves. 

$ python demo.py
INV-2026-0413 is USD 18,450.00; INV-2026-0418 is USD 19,120.00 (tax 7%).
INV-2026-0418 is the higher one, by USD 670.00 (3.63%).

19,120.00 - 18,450.00 = 670.00   check it yourself

What this pattern covers

Document intelligence

Invoices, contracts, purchase orders, quotations. Extraction by model, validation by rules, totals computed — never generated.

Procurement & supplier evaluation

RFQ comparison, commercial deviation flags, bid comparison reports. Deterministic comparison, model-written narrative.

Project controls

Primavera P6 XER and Excel schedules. A real parser for activities, logic links and baselines — an LLM does not read a critical path.

Human-in-the-loop writes

Any state change suspends the graph with interrupt(). No database write happens without an explicit approval.

Stack

Python · LangGraph · FastAPI · PostgreSQL + pgvector (HNSW, permission filtering inside the query) · n8n for integration glue · Docker · self-hosted and offline deployments where client data cannot leave the environment.

What it does not do

  • Field extraction is regex in the demo — real invoice layouts need model extraction plus rule validation, built on the client's own samples.
  • The offline embedder is lexical; it is not a semantic model.
  • The flag action is simulated; a real deployment starts a transaction after approval.

Stated plainly on purpose. A vendor who will not list the limits of a 600-line demo is not going to be honest about the limits of your production system.
